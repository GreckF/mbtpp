# #mbt Types and Traits

Putting `#mbt` before an enum, struct, or trait declares that it corresponds directly to a MoonBit type or trait. Compiled native
code uses these MoonBit types directly, and MoonBit functions can take them without conversion.

```moonbit
#mbt
enum Tree[T] {
  Leaf
  Node(Tree[T], T, Tree[T])
}

#mbt
struct Pt {
  x : Int
  y : Int
}

#mbt
trait Size {
  size(Self) -> Int
}

impl Size for Int with size(self) { self }
impl Size for Pt with size(self) { self.x + self.y }
impl[T : Size] Size for Tree[T] with size(self) {
  match self {
    Leaf => 0
    Node(l, x, r) => l.size() + x.size() + r.size()
  }
}

fn main {
  let t : Tree[Pt] = Node(Leaf, { x: 1, y: 2 }, Leaf)
  println(t.size())
}
```

The output includes `pub(all) enum Tree[T0]`, `pub(all) struct Pt`, `pub(open) trait Size`, and
`impl[T0 : Size] Size for Tree[T0]`.

`#mbt` does not change type checking or interpretation; it only affects compilation. Its conditions are checked during type checking, and an error is reported if they are not met.

## #mbt types

- Only type parameters, no indices; not a proposition and not a `suberror`; constructors have no implicit fields.
- Field types are MoonBit types: `Int`, `Double`, `Bool`, `Char`, `String`, `Unit`, type parameters, `#mbt`
  types, and function types between them. Arrays are not supported yet.
- Generated type and constructor names must start with an uppercase letter and must not clash with existing names such as `Value` or `Option`.

## #mbt("name")

Maps to an existing MoonBit type or trait; no declaration is generated. `Option` and `Result` in the prelude are
`#mbt("Option")` and `#mbt("Result")`. `pub(all)` types and `pub(open)` traits imported from `.mbti` automatically get
`#mbt("@pkg.T")` (when the conditions hold).

## #mbt traits

- `Self : Type`; supertraits are also `#mbt`.
- Methods are not generic; their parameters and results are MoonBit types (`Self` may appear).
- All methods in the generated MoonBit trait are marked `raise` (compiled code implements control flow with errors).
- In native code, a bound `[T : Size]` becomes MoonBit's `fn[T0 : Size]`, and a method call becomes `Size::size(x)`.

## Instances of #mbt traits

- Only type parameters and `#mbt` bounds; `Self` is a MoonBit type (not just a type parameter).
- MoonBit's orphan rule applies: existing traits (`#mbt("…")` or imported) can only be implemented for types generated by this program.
- Read-only (`pub`) traits cannot be implemented.
- Instances whose methods are in the native fragment generate a MoonBit `impl`.

## Finding declarations that could be `#mbt`

`#mbt` is an explicit contract; the compiler never adds it on its own. But `moonpp check` examines enums, structs, traits, and functions
marked `pub` without `#mbt`, and gives a hint for each one that meets the `#mbt` conditions:

```text
src/main/shapes.mbtpp:2: hint: pub type Shape could be #mbt (it would be a MoonBit type)
src/main/shapes.mbtpp:23: hint: pub trait Area could be #mbt (it would be a MoonBit trait)
src/main/shapes.mbtpp:41: hint: pub fn norm1 could be #mbt (it would be exported as a MoonBit function)
  (`moonpp fix` adds #mbt to them)
ok: src/main
```

`moonpp fix` inserts a `#mbt` line above these declarations and re-checks the package; if the check fails, it restores the original files.

- Only `pub` declarations are considered: `pub` has no other meaning in MoonBit++, so here it signals "intended for MoonBit".
- Types and traits are judged together: several mutually referring types can become `#mbt` at once.
- A function needs a translatable signature (assuming the hinted types are annotated) and a body in the native fragment (the same check
  the compiler does).
- Indexed types, types and functions that mention them, and `lemma`s are never hinted.
