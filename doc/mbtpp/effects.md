# MoonBit++ 代数效应提案

## 0. 总体

| 项目 | 决定 |
| --- | --- |
| 声明 | `effect Name[T] { Op(Args) -> R; ctl Op2(Args) -> R }` |
| 函数类型 | 效应写在返回类型上：`-> T!E1 + E2 + e raise Err` |
| 执行 | `perform Op(args)` |
| 处理 | `try { … } catch { Op(x) => { …; resume(v) } }`，深处理器（deep handler） |
| 操作的种类 | 默认是尾恢复操作；`ctl` 操作可以恢复 0 次、1 次或多次（one-shot 与 multi-shot） |
| 效应多态 | 具名效应变量 `!e`；满足"参数不逃逸"时可以省略，由检查器推导，推导结果可见 |
| 纯 | Prelude 中的 `effect pure {}`；没有操作的效应从效应行中去掉，`!pure` 等于纯 |
| `let mut` | multi-shot 下采用恢复语义：每次恢复都从 `perform` 时的值继续 |
| 错误 | `raise` 保持独立，不并入效应行 |
| 逻辑 | 被处理过的计算是纯的，检查期可以计算；效应多态实例化为 `pure` 的调用照常展开 |

## 1. 语法

```moonbit
effect Yield[T] {
  Yield(T) -> Unit            // 尾恢复操作
}

effect Choose {
  ctl Choose() -> Bool        // 一般操作
}

fn[T] iter_array(xs : Array[T]) -> Unit!Yield[T] {
  for x in xs {
    perform Yield(x)
  }
}

fn main {
  try {
    iter_array([1, 2, 3])
  } catch {
    Yield(x) => {
      println(x)
      resume()
    }
  }
}
```

- `Op(Args) -> R`：`perform Op(args)` 的结果类型是 `R`，也就是 `resume` 的参数类型。`R` 为 `Unit` 时
  写 `resume()`。
- `try` 的分支既可以处理错误，也可以处理效应操作；只有效应分支中可以使用 `resume`。
- 深处理器：`resume` 之后，后续的 `perform` 仍由同一个 `try` 处理。
- 效应行：`!E1 + E2 + e`，其中 `e` 是效应变量，写在函数的隐式参数中，例如 `fn[T, e] each(…) -> Unit!e`。
- `raise` 写在效应行之后：`-> Int!State[Int] raise E`。

## 2. 两种操作

| | 尾恢复操作（默认） | `ctl` 操作 |
| --- | --- | --- |
| 分支中的 `resume` | 每条路径的最后一步，恰好一次 | 任意位置，0 次、1 次或多次 |
| 例子 | `Yield`、`State` 的 `Get`/`Put`、日志、Reader | 非确定性、回溯、生成器、提前退出 |
| 编译 | 能力传递：`perform` 是一次函数调用 | 单子化翻译，效应以带延续的值向外传递 |
| 开销 | 几乎为零 | 用到 `ctl` 效应的函数才付出代价 |

**这就是尾恢复优化**：只用尾恢复操作的代码，编译结果和普通函数调用一样，不做任何变换。
检查器会验证尾恢复分支确实以 `resume` 结束，否则报错并提示改用 `ctl`。

尾恢复操作的分支就地运行，不能执行 `ctl` 操作。

## 3. 能力传递（尾恢复操作）

- 每个效应 `E[T]` 对应一个能力类型，它的值是一组闭包，每个操作一个。
- `try … catch` 中有效应分支时，会在 `try` 体中绑定一个局部能力，其中每个闭包运行对应的分支，
  尾部的 `resume(v)` 就是返回 `v`。
- `perform Op(x)` 调用作用域中最内层的能力，查找方式和 trait 的实例参数相同。
- 声明了具体效应的顶层函数，比如 `-> Unit!Yield[T]`，会多出一个实例参数，类型是对应的能力，
  调用时由检查器从作用域中找到并传入。
- lambda 不带能力参数：它在创建时捕获作用域中的能力，处理器的语义因此是词法的。

## 4. `ctl` 操作：单子化翻译

- 用到 `ctl` 效应的函数被翻译成返回计算值：`Pure(v)`，或"执行了一个操作，加上剩余的计算"
  （带一个延续闭包）。
- 函数中对其他这类函数的调用变成绑定（bind）；`perform` 直接产生一个"执行了操作"的值。
- `try` 检查向外传来的操作：属于自己的，就运行分支，`resume(v)` 即"把 `v` 交给延续，并继续由同一个
  处理器处理"；不属于自己的，扩展延续后继续向外传。处理器用运行时生成的唯一标记区分，因此语义仍是
  词法的。
- 错误在翻译后的代码里也是计算值的一种，所以 `resume` 之后的代码抛出的错误仍由原来的 `try` 捕获。
- 延续是普通的闭包，可以调用任意次，multi-shot 不需要额外的运行时支持。
- `let mut` 采用恢复语义：在翻译后的代码中，可变局部变量变成参数传递的状态（循环变成带状态参数的
  递归函数），于是每次恢复都从 `perform` 时的值开始。数组、`mut` 字段、`Ref` 是堆对象，所有恢复共享。
- 效应多态的函数（比如 `each`）在实例化为 `ctl` 效应时，按需生成一个翻译后的版本；实例化为纯或
  尾恢复效应时，使用原来的版本。

翻译在 elaborate 之后、对核心项进行，解释器、检查期执行器和代码生成都不需要另外支持延续。
翻译后的函数使用统一表示（uniform）编译。

## 5. 效应多态

```moonbit
fn[T, e] List::each(self : List[T], f : (T) -> Unit!e) -> Unit!e { … }
```

- `e` 由调用处的合一推断，例如 `xs.each(x => perform Yield(x))` 得到 `e := Yield[T]`。
- **可以省略的条件**：参数 `f` 在函数体内只被直接调用、直接传给另一个效应透明的参数，或者被这样使用的
  lambda 捕获，也就是说 `f` 不会活过这次调用。满足时，省略标注的签名按带 `!e` 的签名处理。Prelude
  的 `each`、`map`、`fold` 因此不用改。
- 不满足时，比如 `f` 被存储、被返回，或者被返回的闭包捕获（`compose`），省略标注就表示纯；需要多态时
  必须写 `!e`。trait 方法和导入的 MoonBit 函数没有可分析的函数体，同样需要显式标注。
- **推导结果可见**：hover、报错信息和接口输出中，都显示推导出的完整签名，并注明 `e` 是推导出来的。
- `!pure` 是显式标注，用来要求参数是纯的，同时关闭推导。

## 6. 逻辑层面

- 证明是纯的，不能执行效应，也不能调用效应非纯的函数。返回证明的函数不能带效应。
- 一个调用是否有效应，按调用处的实例化结果判断：效应多态实例化为 `pure` 的调用是纯调用，检查期照常
  展开，可以在证明中使用和归纳。有效应的调用在类型中保持不展开，适用和 `raise` 相同的值限制。
- **在类型中处理效应**：被 `try … catch` 完整处理的计算是纯的，检查期可以计算。尾恢复处理器经过能力
  传递之后就是普通的闭包传递，参数是变量时也能展开，例如

  ```text
  try { each(xs, x => perform Yield(x)) } catch { Yield(x) => { h(x); resume() } }
    ≡ each(xs, x => h(x))
  ```

  处理分支修改外层 `let mut` 时，只有参数是具体值时才能运行。
- 未处理的效应不会被展开成值（"操作树"语义留作以后的工作）。

## 7. 限制

- 尾恢复操作的分支不能执行 `ctl` 操作。
- 一个 `try` 不能同时处理错误和 `ctl` 操作；处理错误的 `try … catch` 和 `defer` 不能包住执行 `ctl`
  操作的代码（翻译后的代码中，错误仍是宿主的异常）。
- 效应不能跨包使用（接口文件中没有效应声明）。
- 能力被词法捕获，捕获了能力的闭包如果逃出了 `try`，之后调用时仍会运行原处理器的分支。
- trait 方法和 trait 对象暂不支持效应多态的推导，需要显式标注。
- 用到 `ctl` 效应的代码只使用统一表示编译，性能低于原生代码。
- 效应和 `async` 暂不组合。

## 8. 阶段

1. 声明、效应行、`perform`、尾恢复处理器（能力传递），以及检查期计算。
2. 效应多态 `!e`、推导、`pure`，以及按实例化结果判断调用是否有效应。
3. `ctl` 操作：单子化翻译、标记、错误和 `let mut` 的处理，以及按需生成的翻译版本。
4. 文档与测试。
