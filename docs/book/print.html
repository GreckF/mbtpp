MoonBit++ 手册

MoonBit++ 手册

MoonBit++ 是一门依赖类型语言，语法取自 MoonBit：同样的 fn、enum、struct、trait、 match、let mut、for、raise，加上依赖类型、索引类型、依赖模式匹配、命题与证明。

它包括：

  • 类型检查器：依赖类型、合一、依赖模式匹配与覆盖检查、实例搜索、简单的策略。
  • 解释器：直接运行类型检查后的程序。
  • 编译器：把程序翻译成 MoonBit，能用 MoonBit 类型表达的部分生成原生代码。
  • moonpp：类似 moon 的命令行工具，管理项目、依赖与构建。

这是一个纯 vibe coding 的娱乐项目，请不要认真看待。类型检查器不做终止检查，证明可以靠 无限递归“证”出任何命题，不适合任何正式用途。

本手册分三部分：

  • 语言：从词法到证明、trait、副作用，每个特性一章。
  • moonpp：安装、项目结构、命令、依赖、构建产物。
  • 与 MoonBit 交互：导入 MoonBit 包、编译到 MoonBit、#mbt 声明、在 MoonBit 中使用编译结果。

带 fn main 的示例右上角有 ▶ 按钮，可以在 Playground 中打开 运行。源码与示例在 GitHub。

快速开始

安装 moonpp（见安装）后：

moonpp new hello
cd hello
moonpp run                # 用解释器运行 src/main
moonpp check              # 类型检查
moonpp run --compiled     # 编译到 MoonBit 再运行
moonpp build              # 编译成 MoonBit 项目 mbtpp_out/main

moonpp new 生成的 src/main/main.mbtpp 类似这样：

enum Vector[T] : Nat -> Type {
  Nil : Vector[T](0)
  Cons[n : Nat](T, Vector[T](n)) : Vector[T](S(n))
}

// 只接受非空向量：不需要 Nil 的分支
fn[T, n : Nat] Vector::head(self : Vector[T](S(n))) -> T {
  match self {
    Cons(x, _) => x
  }
}

fn main {
  let v : Vector[String](2) = Cons("Hello", Cons("MoonBit++", Nil))
  println(v.head())
}
  • Vector[T](n) 是长度为 n 的向量：T 是参数，n 是索引（见 enum 与索引类型）。
  • head 只接受类型为 Vector[T](S(n)) 的向量，所以 Nil 不可能出现，match 不需要它的分支 （见覆盖检查与不可能分支）。
  • v.head() 调用方法 Vector::head。

不安装也可以在 Playground 中试用。

表达式与语句

表达式和语句与 MoonBit 一致：

fn demo(xs : Array[Int]) -> Int {
  let a = 1                       // 不可变绑定
  let mut total = a               // 可变绑定
  total = total + 2               // 赋值
  for x in xs {
    total = total + x
  }
  let f = (x : Int) => x * 2      // lambda；也可写 x => e、(x, y) => e
  let g = fn(x : Int) { x + 1 }   // 匿名函数
  let s = if total > 10 { "big" } else { "small" }
  println(s)
  total |> f |> g                 // 管道
}

fn main {
  println(demo([1, 2, 3]))
}
  • 块：{ s1; s2; e } 的值是最后一个表达式。
  • let：let x = e、let x : T = e；模式绑定 let (a, b) = pair（做覆盖检查）。
  • if：if c { a } else { b } 是表达式；没有 else 时值为 ()。
  • lambda：x => e、(x, y) => e、(x : Int) => e、fn(x : Int) { … }。
  • 管道：e |> f 即 f(e)，e |> f(a) 即 f(e, a)。
  • 类型注解：(e : T)。
  • 洞：_ 由合一推断，可以出现在表达式和类型中，例如 Cons(_, xs)、f[_, Int](x)。
  • 局部函数：块内可以写 fn name(x : T) -> R { … }，但不能递归。
  • 数组：xs[i] 取元素，xs[i] = v 赋值。

三种等号：= 定义，== 布尔相等（结果是 Bool），=== 命题相等（结果是 Prop，见 命题相等）。

循环、return、break、continue 见可变状态与循环，raise、try 见 错误处理。

函数

fn add(x : Int, y : Int) -> Int {
  x + y
}

fn[T] twice(f : (T) -> T, x : T) -> T {   // [T]：隐式参数
  f(f(x))
}

fn answer() -> Int { 42 }                 // 无参数函数

fn main {
  println(add(1, 2))
  println(twice(x => x + 1, 0))
  println(twice[Int](x => x * 2, 1))      // 显式给出隐式参数

}

不柯里化

函数接受一组参数：(Int, Int) -> Int 接受两个参数，和返回函数的 (Int) -> (Int) -> Int 是不同的类型。不允许部分应用。

无参数的函数（fn answer()）内部表示为接受一个 Unit 参数。

隐式参数

隐式参数写在 fn 后面的 [...] 中：

fn[T] count(xs : Array[T], extra : Nat) -> Nat {
  plus(xs.size(), extra)
}

fn main {
  println(count([1, 2], 3).to_int())
}
  • [T] 即 [T : Type]。不写类型的隐式参数，类型由使用推断，推断不出时默认为 Type。
  • 调用时一般由合一推断。也可以用 f[a, b](x) 按位置显式给出：可以只给前缀，可以写 _。
  • 隐式参数只能写在 fn 后面，不支持 fn f[T](...)。

其他形式

  • 方法：fn Type::m(self : Type, …)，见方法与运算符。
  • 带标签参数：x~ : T、x? : T，见带标签参数。
  • lemma：结果是命题的函数，见 lemma。
  • 外部原语：fn f(x : Int) -> Int = "%prim_name"，只用于 Prelude。
  • main：fn main { … }，程序入口。

带标签参数

与 MoonBit 相同：

fn greet(name~ : String, greeting~ : String = "Hello", title? : String) -> String {
  match title {
    Some(t) => greeting + ", " + t + " " + name
    None => greeting + ", " + name
  }
}

fn main {
  println(greet(name="Alice"))
  println(greet(greeting="Hi", name="Bob", title="Dr."))
  let name = "Carol"
  println(greet(name~))            // name~ 即 name=name
  let t : String? = None
  println(greet(name~, title?=t))  // title?= 直接传 Option
}
声明调用说明
x~ : Tf(x=e)、f(x~)必须传
x~ : T = d可以省略默认值 d 可以引用前面的参数，每次调用时求值
x? : Tf(x=e)、f(x?=opt)、省略函数体内的类型是 T?，省略时为 None
  • 带标签参数可以按任意顺序传，也可以和位置参数交错。
  • 只有顶层函数（包括方法）能有带标签参数，lambda 和局部函数不能。
  • 作为值使用时，函数类型只按声明顺序列出参数，不含标签。

方法与运算符

方法

fn Type::m(self : Type, …) 定义类型 Type 的方法。x.m(a) 调用 T::m(x, a)，T 是 x 的 类型的头部；也可以写 Type::m(x, a)。

enum Color {
  Red
  Green
}

fn Color::name(self : Color) -> String {
  match self {
    Red => "red"
    Green => "green"
  }
}

fn main {
  println(Red.name())
  println(Color::name(Green))
}

x.m() 先找类型自己的方法，再找 trait 方法（见 trait）。

类型

宇宙

  • Type : Type：类型本身是值，类型的类型是 Type（因此不一致，见介绍中的声明）。
  • Prop : Type：命题的宇宙。Prop 中类型的值是证明；证明无关，任意两个同类型的证明视为相等。 见命题与证明。

函数类型

写法含义
(Int, Int) -> Int接受两个参数的函数
(Int) -> (Int) -> Int返回函数的函数
(n : Nat, v : Vector[Int](n)) -> Int依赖函数类型：后面的类型可以引用前面的参数
forall x : A, P(x)即 (x : A) -> P(x)；forall x y : A, … 绑定多个
[T](x : T) -> T一组参数，隐式在前、显式在后

(A) -> B raise E可能抛出错误 E 的函数
 
fn types_demo() -> Int {
  let f : (Int, Int) -> Int = (a, b) => a + b       // 两个参数
  let g : (Int) -> (Int) -> Int = a => b => a + b   // 返回函数的函数
  f(1, 2) + g(1)(2)
}

fn main {
  println(types_demo())
}

应用与简写

  • 类型也是函数，Array[Int]、Vector[T](n)、Id[T](x)(y) 都是普通的应用：[...] 给隐式 参数，(...) 给显式参数。
  • T? 即 Option[T]；(A, B) 是二元组类型。
  • 返回 Type 的函数就是类型层的函数，见类型层计算。

类型层计算

类型是值，所以可以用普通函数计算类型，类型检查时会规范化（计算）它们：

// 接受 n 个 Int 参数、返回 Int 的函数类型
fn NAry(n : Nat) -> Type {
  match n {
    Z => Int
    S(k) => (Int) -> NAry(k)
  }
}

fn sum_n(n : Nat, acc : Int) -> NAry(n) {
  match n as m return NAry(m) {
    Z => acc
    S(k) => x => sum_n(k, acc + x)
  }
}

fn main {
  println(sum_n(3, 0)(1)(2)(3))   // 6
}

sum_n(3, 0) 的类型 NAry(3) 在类型检查时被计算成 (Int) -> (Int) -> (Int) -> Int。 这里用 return 子句 给出了匹配的动机。

类型检查时会展开的只有纯函数：使用了可变状态、循环或异常的函数不展开（见 可变状态与循环）。

参数与索引

enum 名字[隐式参数](显式参数) : 索引 -> 宇宙 { 构造子 }
  • 参数写在名字后，在所有构造子中固定。
  • 索引写在冒号后，可以随构造子变化。宇宙是 Type 或 Prop。
  • 构造子：C[自己的隐式参数](字段) : 返回类型。没有索引时可以省略返回类型。
enum Vector[T] : Nat -> Type {
  Nil : Vector[T](0)
  Cons[n : Nat](T, Vector[T](n)) : Vector[T](S(n))
}

// 索引写在 [] 中：GADT
enum Exp : [T] -> Type {
  IntLit(Int) : Exp[Int]
  BoolLit(Bool) : Exp[Bool]
  Add(Exp[Int], Exp[Int]) : Exp[Int]
  If[T](Exp[Bool], Exp[T], Exp[T]) : Exp[T]
}

fn[T] Exp::eval(self : Exp[T]) -> T {
  match self {
    IntLit(n) => n
    BoolLit(b) => b
    Add(l, r) => l.eval() + r.eval()
    If(c, t, f) => if c.eval() { t.eval() } else { f.eval() }
  }
}

fn main {
  let e = If(BoolLit(true), Add(IntLit(1), IntLit(2)), IntLit(0))
  println(e.eval())
}

Exp::eval 的结果类型随构造子变化：匹配到 IntLit(n) 时 T 被细化为 Int。

命名字段

构造子的字段可以命名，后面的字段的类型可以引用它：

enum Sigma[A](P : (A) -> Type) {
  MkSigma(fst : A, snd : P(fst))
}

使用构造子

  • 数据类型的参数总是推断的；[...] 只给构造子自己的隐式参数，例如 Cons[n](x, xs)。
  • 重名构造子按期望类型区分，也可以写全名 Vector::Cons。
  • 宇宙为 Prop 的 enum 是命题，例如 Prelude 中的 Id（见命题相等）。

struct 与依赖字段

struct Point {
  x : Int
  y : Int

fn main {
  let p : Point = { x: 1, y: 2 }

  • 构造：{ x: 1, y: 2 }，类型由期望类型决定。
  • 字段访问：p.x。

依赖字段

后面的字段可以依赖前面的字段，例如一个带长度证明的数组：

struct Vec[T, n : Nat] {
  to_array : Array[T]
  length_to_array : to_array.size() === n
}

fn[T] Vec::from_array(xs : Array[T]) -> Vec[T, xs.size()] {
  { to_array: xs, length_to_array: Refl }
}

fn[T, n : Nat] Vec::get(self : Vec[T, n], i : Int) -> T {
  self.to_array[i]
}

fn main {
  let v = Vec::from_array([1, 2, 3])
  println(v.get(1))
}

xs.size() 返回 Nat，所以可以出现在类型中；xs.length() 返回 Int。

模式匹配

match 的写法与 MoonBit 相同：

fn describe(n : Int, xs : List[Int]) -> String {
  match (n, xs) {
    (0, _) => "zero"
    (_, Nil) => "empty"
    (_, Cons(x, Cons(_, _))) => "at least two, starting with \{x}"
    _ => "other"
  }
}

fn main {
  println(describe(1, Cons(7, Cons(8, Nil))))
}
  • 模式：变量、通配符 _、构造子（可以嵌套）、字面量、元组。
  • 分支按顺序匹配，可以重叠，第一个匹配的分支生效。
  • 构造子的隐式参数可以在模式中绑定或忽略：If[t](c, a, b)、IZ[_, a] => a。
  • let 模式：let (a, b) = pair。

MoonBit++ 的模式匹配是依赖的：

  • 依赖匹配与细化：匹配一个构造子时，类型中的索引随之细化。
  • 覆盖检查与不可能分支：缺少的分支会报错，类型上不可能的分支可以省略。
  • return 子句：显式给出匹配的动机（Rocq 风格）。

依赖匹配与细化

匹配一个变量时，构造子的索引与变量类型中的索引做合一，结果细化整个上下文和目标类型 （Agda 风格）：

enum Vec2[T] : Nat -> Type {
  VNil : Vec2[T](0)
  VCons[n : Nat](T, Vec2[T](n)) : Vec2[T](S(n))
}

fn[T, n : Nat] Vec2::zip_with(self : Vec2[T](n), other : Vec2[T](n), f : (T, T) -> T) -> Vec2[T](n) {
  match (self, other) {
    (VNil, VNil) => VNil
    (VCons(x, xs), VCons(y, ys)) => VCons(f(x, y), xs.zip_with(ys, f))
  }
}

fn main {
  let v : Vec2[Int](2) = VCons(1, VCons(2, VNil))
  match v.zip_with(v, (a, b) => a + b) {
    VCons(x, _) => println(x)
  }
}
  • 匹配 self 得到 VNil 时，合一得出 n = 0。于是 other : Vec2[T](0) 只能是 VNil， (VNil, VCons(…)) 这样的组合不需要写。
  • 每个分支中，目标类型 Vec2[T](n) 也被细化：VNil 分支返回 Vec2[T](0)，VCons 分支返回 Vec2[T](S(n'))。
  • 匹配隐式参数也会细化，例如 match g { Empty => …; Extend(_, _) => … }，其中 g 是函数的 隐式参数。

匹配函数调用的结果

被匹配的不是变量（例如函数调用）时，结果类型中的索引关系同样用于细化目标类型：

match progress(t1) {
  PrStep(_, u1, st1) => PrStep(_, _, StApp1(t1, u1, t2, st1))
  PrDone(_, VLam(b)) => PrStep(_, _, StApp(b, t2))
}

完整的例子见仓库中的 examples/stlc.mbtpp。

Prop 的消去

匹配 Prop 中的数据时，结果也必须在 Prop 中，除非这个类型是子单例（如命题相等 ===， 它最多只有一个证明）。

覆盖检查与不可能分支

每个 match 都要覆盖所有情况，否则报错：

t.mbtpp:2:3: error: match is not exhaustive; missing case(s):
  S(_)

不可能的分支

构造子的索引与被匹配的类型合一失败时，这个分支不可能出现，可以省略：

enum Fin : (Nat) -> Type {
  FZ[n : Nat] : Fin(S(n))
  FS[n : Nat](Fin(n)) : Fin(S(n))
}

enum Vector[T] : Nat -> Type {
  Nil : Vector[T](0)
  Cons[n : Nat](T, Vector[T](n)) : Vector[T](S(n))
}

// 不需要 Nil 的分支：Fin(0) 是空类型，Nil 不可能与 Fin(n) 同时出现
fn[T, n : Nat] Vector::get(self : Vector[T](n), i : Fin(n)) -> T {
  match (self, i) {
    (Cons(x, _), FZ) => x
    (Cons(_, xs), FS(j)) => xs.get(j)
  }
}

fn main {
  let v : Vector[String](3) = Cons("a", Cons("b", Cons("c", Nil)))
  println(v.get(FS(FS(FZ))))
}

也可以只写模式、不写 =>，此时检查器会确认它确实不可能（写错了会报“this pattern is not impossible”）：

enum V3[T] : Nat -> Type {
  N3 : V3[T](0)
  C3[n : Nat](T, V3[T](n)) : V3[T](S(n))
}

fn[T, n : Nat] V3::head(self : V3[T](S(n))) -> T {
  match self {
    N3
    C3(x, _) => x
  }
}

空类型

没有构造子能匹配的类型是空类型，对它的匹配可以没有分支。检查器会在嵌套的位置识别空类型， 例如字段类型为 Fin(0) 的构造子不必列出。内置类型（Int、Array 等）不是空类型。

return 子句

match e as x in D[_](i) return P(i, x) { … }

Rocq 风格的匹配：显式给出动机 P，即每个分支的结果类型如何依赖于被匹配的值 x 和它的索引 i。

enum Vector[T] : Nat -> Type {
  Nil : Vector[T](0)
  Cons[n : Nat](T, Vector[T](n)) : Vector[T](S(n))
}

fn[T, n : Nat] Vector::length_eq(self : Vector[T](n)) -> Nat {
  match self as v in Vector[_](m) return Nat {
    Nil => Z
    Cons(_, xs) => S(xs.length_eq())
  }
}

fn main {
  let v : Vector[Int](2) = Cons(7, Cons(8, Nil))
  println(v.length_eq().to_int())
}
  • as x 给被匹配的值命名，in D[_](i) 给它的类型中的索引命名，return P 是动机；三部分都 可以省略（如类型层计算中的 match n as m return NAry(m)）。
  • 有 return 时按 Rocq 的语义，不细化上下文；没有 return 时按 依赖匹配与细化。

命题与证明

命题是 Prop 中的类型，证明是它们的值。类型检查器在检查证明时会计算（规范化）表达式，所以 很多等式可以直接由计算得出。

  • 命题相等：===、Refl 与 Prelude 中的等式引理。
  • lemma：声明定理。
  • 策略：用 proof { … } 一步步构造证明。

自定义的命题是宇宙为 Prop 的 enum：

enum And[A : Prop, B : Prop] : Prop {
  Conj(A, B)
}

lemma and_comm[A : Prop, B : Prop](p : And[A, B]) -> And[B, A] {
  match p {
    Conj(a, b) => Conj(b, a)
  }
}

没有终止检查和严格正性检查：递归函数和递归证明都直接接受，因此可以“证明”假命题。证明在 编译时也不擦除。

命题相等

a === b 是 Prelude 中的 Id[_](a)(b)：

enum Id[T](x : T) : (y : T) -> Prop {
  Refl : Id[T](x)(x)
}

Refl 是唯一的构造子，它证明 x === x。因为类型检查时会计算，两边规范化后相同的等式都可以 直接用 Refl 证明：

lemma two_plus_two : (2 : Nat) + 2 === 4 = Refl

lemma plus_zero_left(n : Nat) -> (0 : Nat) + n === n {
  Refl
}

0 + n 按 Nat::op_add 的定义计算为 n；n + 0 则不能直接计算（n 是变量），需要归纳， 见 lemma。

等式引理

引理类型
Id::sym(p)x === y 推出 y === x
Id::trans(p, q)x === y、y === z 推出 x === z
Id::cong(f, p)x === y 推出 f(x) === f(y)
Id::subst(p, motive, px)x === y 与 motive(x) 推出 motive(y)；motive 可以返回 Type

=== 是子单例，所以可以匹配 Refl 来改写类型，即使结果在 Type 中：

fn[a : Nat, b : Nat] cast(e : a === b, xs : Array[Int]) -> Array[Int] {
  match e {
    Refl => xs
  }
}

== 与 === 不同：== 是 Bool 值的比较，可以在运行时计算；=== 是命题。

lemma

lemma 与 fn 相同，只是结果通常是命题。有两种写法：

  • lemma 名字[隐式](参数) -> 命题 { 证明 }
  • lemma 名字[隐式] : 命题 = 证明表达式

用模式匹配和递归做归纳：

lemma plus_zero(n : Nat) -> n + 0 === n {
  match n {
    Z => Refl
    S(k) => Id::cong(S, plus_zero(k))
  }
}

lemma plus_succ(n : Nat, m : Nat) -> n + S(m) === S(n + m) {
  match n {
    Z => Refl
    S(k) => Id::cong(S, plus_succ(k, m))
  }
}

lemma append_nil[T](xs : List[T]) -> xs.append(Nil) === xs {
  match xs {
    Nil => Refl
    Cons(x, rest) => Id::cong(r => List::Cons(x, r), append_nil(rest))
  }
}
  • Z 分支中目标 0 + 0 === 0 计算后两边相同，用 Refl。
  • S(k) 分支中目标是 S(k) + 0 === S(k)，计算为 S(k + 0) === S(k)；用递归得到的 k + 0 === k 加上 Id::cong(S, …) 得出。
  • 递归调用就是归纳假设。检查器不验证递归是否终止。

更长的证明见仓库中的 examples/proofs.mbtpp（向量拼接的结合律、reverse 的性质）和 examples/stlc.mbtpp（简单类型 λ 演算的代换引理、progress 与 canonicity，以及从 canonicity 证明中提取求值器）。

策略

proof { … } 用策略一步步构造证明，每行一条：

lemma plus_zero(n : Nat) -> n + 0 === n {
  match n {
    Z => Refl
    S(k) => Id::cong(S, plus_zero(k))
  }
}

lemma plus_succ(n : Nat, m : Nat) -> n + S(m) === S(n + m) {
  match n {
    Z => Refl
    S(k) => Id::cong(S, plus_succ(k, m))
  }
}

lemma plus_comm : forall n m : Nat, n + m === m + n = proof {
  intros n m
  destruct n
  rewrite plus_zero(m)
  rfl
  rewrite plus_succ(m, n_0)
  rewrite plus_comm(n_0, m)
  rfl
}
策略作用
intros x y引入假设（也写 intro；_ 忽略）
exact e用表达式 e 完成当前目标
rfl用 Refl 完成目标（两边规范化后相同）
destruct x对 x 分情况，每个构造子一个新目标；字段命名为 x_0、x_1…（也写 cases）
rewrite e、rewrite <- e用等式 e 从左到右、从右到左改写目标（也写 rw）
apply f用函数 f 把目标归约为它的参数
assume h : P先把 P 作为假设 h 使用，之后再证明 P（也写 have）

更多例子：

enum And[A : Prop, B : Prop] : Prop {
  Conj(A, B)
}

lemma and_comm[A : Prop, B : Prop] : (And[A, B]) -> And[B, A] = proof {
  intros p
  destruct p
  exact Conj(p_1, p_0)
}

lemma modus_ponens[A : Prop, B : Prop] : (A, (A) -> B) -> B = proof {
  intros a f
  apply f
  exact a
}

lemma zero_ne_one : (0 : Nat) === 1 -> Int = proof {
  intros h
  destruct h
}
  • 策略只是构造证明项的另一种方式，结果与手写的项相同。
  • 对不可能的等式（如 0 === 1）做 destruct 没有剩余目标。
  • 没有 simp、omega、auto 这类自动化策略。

trait

trait Shape {
  area(Self) -> Int
  name(Self) -> String
}

trait Solid : Shape {                          // 父 trait
  volume(Self, Int) -> Int
}

struct Square {
  side : Int
}

impl Shape for Square with area(self) { self.side * self.side }
impl Shape for Square with name(self) { "square" }
impl Solid for Square with volume(self, depth) { self.area() * depth }

fn[S : Shape] describe(s : S) -> String {
  "\{s.name()} with area \{s.area()}"
}

fn[S : Solid] describe_solid(s : S) -> String {
  describe(s) + ", volume \{s.volume(2)}"     // 父 trait 的方法可用
}

fn main {
  let sq : Square = { side: 2 }
  println(describe_solid(sq))
}
  • 声明：trait Name : Super1 + Super2 { 方法(参数类型) -> 结果 }，方法的第一个参数通常是 Self。泛型方法写 fn[T] m(…)。
  • 实现：impl Tr for T with m(参数) { … }，每个方法一条。泛型实例： impl[T : Show] Show for Array[T] with to_string(self) { … }。
  • 约束：fn[T : Tr]，多个约束 [T : Eq + Show]。
  • 调用：x.m() 或 Tr::m(x)。

约束与隐式参数

[T : Add] 和 [n : Nat] 写法相同，由冒号右边的名字区分：

  • 右边是 trait（或用 + 连接的几个 trait）时，这是约束：T 是一个类型（种类由 trait 的 Self 决定：Add 的是 Type，Monad 的是 [T] -> Type），每个 trait 另有一个由检查器 自动填充的实例参数。读作“实现了 Add 的类型 T”。
  • 右边是类型时，这是普通的隐式参数：n 是 Nat 的一个值，例如 fn[T, n : Nat] Vector::head(…)。

trait 和类型在同一个命名空间中，不能同名，所以不会有歧义。注意：

  • 这条规则只用于 [...]。显式参数 (x : Add) 按类型检查，会报错：没有 MoonBit 的 trait 对象 &Add。
  • 局部名字优先：如果外层有与 trait 同名的参数，冒号右边指的是那个参数。
  • 多个约束的种类要相同（T 的种类取自第一个 trait），[M : Monad + Show] 会报错。
  • 实例搜索：约束对应的实例由检查器自动填充：先找局部约束（以及它们的父 trait），再找全局 实例（包括泛型实例）。

Prelude 中的 trait：Show（to_string）、Eq（op_equal）、Compare : Eq（compare）、 Add（op_add）、Monad（见高阶 trait 与 monad）。println 需要 Show。

高阶 trait 与 monad

Self 可以是类型构造子。Prelude 中的 Monad：

trait Monad(Self : [T] -> Type) {
  fn[T] pure(T) -> Self[T]
  fn[T, U] bind(Self[T], (T) -> Self[U]) -> Self[U]
}

Option 和 List 有 Monad 实例。

monad 块

fn[M : Monad, T, U, V] lift2(f : (T, U) -> V, m : M[T], n : M[U]) -> M[V] {
  monad {
    let t <- m
    let u <- n
    Monad::pure(f(t, u))
  }
}

fn[M : Monad, T, U, V] lift2_inline(f : (T, U) -> V, m : M[T], n : M[U]) -> M[V] {
  monad {
    Monad::pure(f(<- m, <- n))
  }
}

fn main {
  println(lift2((a, b) => a + b, Some(1), Some(2)))
  println(lift2_inline((a, b) => a + b, Some(1), None))
  let xs : List[Int] = Cons(1, Cons(2, Nil))
  let ys : List[Int] = Cons(10, Cons(20, Nil))
  println(lift2_inline((a, b) => a * b, xs, ys))
}
  • let x <- m 绑定 m 的结果，之后的语句在 bind 的回调中。
  • 表达式中的 <- m 就地绑定，按从左到右的顺序。
  • monad { … } 的类型由期望类型或其中的表达式推断出用哪个 Monad 实例。

可变状态与循环

fn sum_to(n : Int) -> Int {
  let mut acc = 0
  for i = 1; i <= n; i = i + 1 {
    acc = acc + i
  }
  acc
}

fn find_first(xs : Array[Int], p : (Int) -> Bool) -> Int {
  for x in xs {
    if p(x) {
      return x
    }
  }
  -1
}

fn main {
  println(sum_to(100))
  println(find_first([1, 5, 8, 11], x => x % 2 == 0))
  let mut i = 0
  while true {
    i += 1
    if i > 5 {
      break
    }
  }
  println("i = \{i}")
  let arr = Array::make(3, 0)
  arr[1] = 42
  for k in 0..<3 {
    print(arr[k])
    print(" ")
  }
  println("")
}
  • 可变变量：let mut x = e，赋值 x = e，以及 +=、-=、*=、/=。
  • 循环：while c { … }；C 风格 for i = 0; i < n; i = i + 1 { … }；for x in xs { … } 遍历数组；for k in a..<b、for k in a..=b 遍历区间。
  • break、continue 作用于最内层循环；return 从当前函数返回，在 lambda 中只从 lambda 返回。
  • 数组是可变的：xs[i] = v、xs.push(x)。

与类型检查的关系

使用了 let mut、赋值、循环、raise、try 的函数在类型检查时不展开：它们可以正常调用、 运行，但不参与类型层的计算，关于它们的等式不能用 Refl 证明。

错误处理

suberror DivError {
  DivError(String)
}

fn div(a : Int, b : Int) -> Int raise DivError {
  if b == 0 {
    raise DivError("division by zero")
  }
  a / b
}

fn main {
  let r = try div(10, 0) catch {
    DivError(msg) => {
      println("caught: " + msg)
      0
    }
  }
  println(r)
  println(try? div(10, 2))      // Ok(5)
}
  • 错误类型：suberror Name { C(…) }，或单个构造子的简写 suberror Name(String)。
  • 声明：函数类型 -> T raise E；raise 不写类型时为 Error（任何错误）。
  • 抛出：raise e。
  • 捕获：try e catch { 模式 => … }，分支按错误的构造子匹配，没有匹配的错误继续向外抛出。
  • try? e：得到 Result[T, Error]，不抛出。
  • Prelude 中的 fail(msg) 抛出 Failure(msg)。

raise、try 与可变状态一样，使函数在类型检查时不展开（见 可变状态与循环）。

检查顺序

一个包的文件按文件名的字典序依次检查。名字可以互相引用（定义在后面的函数也能调用），但类型 检查时的计算只能用已经检查过的函数体：如果 facts.mbtpp 中的证明要计算 shapes.mbtpp 中 定义的函数，shapes.mbtpp 必须先检查。这时用 "mbtpp-order" 指定顺序：

options(
  "is-main": true,
  "mbtpp-order": [ "shapes.mbtpp" ],
)

列出的文件先检查（按列出的顺序），其余文件仍按字典序在后面。旧格式的 moon.pkg.json 中写 "mbtpp-order": [ "shapes.mbtpp" ]。moon 会忽略这个选项，moon fmt 会保留它。

如果一个错误可能是检查顺序造成的，moonpp 会给出提示：

src/main/facts.mbtpp:1:47: error: type mismatch
  expected: Shape::area(Rect(3, 3)) === 9
  actual:   ?94 === ?94
hint: Shape::area is defined in src/main/shapes.mbtpp, which is checked after
src/main/facts.mbtpp, so its definition could not be used here; the error may
come from that. … list it in the package's moon.pkg: options("mbtpp-order": [ "shapes.mbtpp", ... ])

旧格式

旧的 moon.mod.json、moon.pkg.json 也能读取。但新版 moon 不再接受 moon.mod.json，所以 需要依赖管理或编译时，在项目根目录运行 moon fmt 迁移；moonpp 遇到这种情况会给出提示。

功能

  • 语法高亮：包括 proof { ... } 中的策略。
  • 诊断：编辑时（默认停顿 300 毫秒后）检查文件所在的包，未保存的内容也算在内。检查器遇到 第一个错误就停止，所以一次显示一个错误。可以标 #mbt 的 pub 声明显示为提示，快速修复 （灯泡）“Add #mbt” 会插入标注，“Add #mbt everywhere possible” 运行 moonpp fix。
  • 悬停：变量、函数、方法、字段、构造子（包括模式中的）、类型的类型。
  • 跳转到定义（Ctrl+单击、F12）：包中的全局定义。
  • 符号：大纲和 Ctrl+Shift+O 列出文件中的声明（构造子、字段、方法在其类型之下）；Ctrl+T 在 工作区所有 .mbtpp 文件的声明中搜索。
  • Info view（编辑器标题栏的按钮，或 Ctrl+Shift+Enter）：光标在 proof { ... } 中时，显示 光标处策略执行后的目标（假设和 ⊢ 目标）；在第一个策略之前显示初始目标；策略失败时显示 执行它之前的目标和错误。光标在其他地方时显示光标处名字的类型。
  • 命令：MoonBit++: Run（标题栏的 ▶）、Run Compiled、Check、Build MoonBit Project、 Add #mbt Where Possible，在终端中运行对应的 moonpp 命令。

例如，光标在下面第二个策略上时：

编译到 MoonBit

编译器把类型检查后的程序翻译成 MoonBit。moonpp build 和 moonpp run --compiled 使用它； Playground 中的“编译到 MoonBit”可以直接查看结果。

两种翻译混合使用：

原生翻译

参数和结果都是原生类型、函数体也在一阶片段中的函数，翻译成普通的（可以是泛型的）MoonBit 函数。原生类型是：

  • Int、Double、Bool、Char、String、Unit；
  • 类型参数和函数类型；
  • 参数都是类型、字段都是原生类型的数据类型。

索引和被擦除的字段消失，例如：

enum Vector[T] : Nat -> Type { Nil : …; Cons[n : Nat](T, Vector[T](n)) : … }
// 编译为
enum E_Vector[T0] { Nil; Cons(T0, E_Vector[T0]) }

#mbt 类型使用自己的名字而不是 E_…（见 #mbt 类型与 trait）。

统一表示

其余部分（类型层计算、GADT 细化、非 #mbt 的 trait 等）使用统一值表示 Value。它是运行时 中的一个可扩展 enum（MoonBit 的 extenum），固定变体是 VInt、VFun 等；每个生成的文件用 extenum Value += { … } 加入自己的数据类型中用到的构造子，索引和被擦除的字段不出现，字段是 Value。例如 basic.mbtpp 的 GADT：

enum Exp : [T] -> Type {
  IntLit(Int) : Exp[Int]
  Add(Exp[Int], Exp[Int]) : Exp[Int]
  If[T](Exp[Bool], Exp[T], Exp[T]) : Exp[T]
  …
}

在 basic.mbt 中编译为

extenum Value += {
  K_Exp_IntLit(Value)
  K_Exp_Add(Value, Value)
  K_Exp_If(Value, Value, Value)
  …
}

eval 中的 match 是原生的：

fn f19_exp_eval(self : Value) -> Value raise {
  match self {
    K_Exp_IntLit(n) => n
    K_Exp_Add(lhs, rhs) => VInt(as_int(f19_exp_eval(lhs)) + as_int(f19_exp_eval(rhs)))
    …
  }
}

eval 的结果类型随索引变化（IntLit 分支返回 Int，BoolLit 分支返回 Bool），MoonBit 的类型系统表达不了，所以它的结果仍是 Value。运行时支持（apply、原语、动态模式匹配器）在 生成的 mbtpp_runtime.mbt 中；它通过各文件在 fn init 中注册的解码器得到构造子的名字和字段 （用于显示与相等比较）。两种代码之间在边界上转换。

因为 Value 可以从别的文件、别的包扩展，这种表示也适合将来分别编译多个 MoonBit++ 包。

擦除

  • 类型参数总是擦除。
  • 其他隐式参数和构造子的隐式字段只用于类型时擦除。
  • 证明不擦除：它们和普通值一样被计算。

性能

一个 fib 程序编译后约快 40 倍（解释器 7.85 秒，编译后 0.18 秒）。构造子成为 Value 的原生 变体之前，统一表示中的数据是 VCon(构造子名, 字段数组)，匹配要比较字符串；改为原生变体后， 对一棵 2^18 个叶子的 Exp 树求值 20 次，从 2.65 秒降到 1.26 秒。

#mbt 类型与 trait

在 enum、struct、trait 前加 #mbt，声明它们直接对应 MoonBit 的类型和 trait。编译后的原生 代码直接使用这些 MoonBit 类型，MoonBit 函数可以不经转换地接收它们。

#mbt
enum Tree[T] {
  Leaf
  Node(Tree[T], T, Tree[T])
}

#mbt
struct Pt {
  x : Int
  y : Int
}

#mbt
trait Size {
  size(Self) -> Int
}

impl Size for Int with size(self) { self }
impl Size for Pt with size(self) { self.x + self.y }
impl[T : Size] Size for Tree[T] with size(self) {
  match self {
    Leaf => 0
    Node(l, x, r) => l.size() + x.size() + r.size()
  }
}

fn main {
  let t : Tree[Pt] = Node(Leaf, { x: 1, y: 2 }, Leaf)
  println(t.size())
}

编译结果包括 pub(all) enum Tree[T0]、pub(all) struct Pt、pub(open) trait Size、 impl[T0 : Size] Size for Tree[T0]。

#mbt 不改变类型检查和解释执行，只影响编译。条件在类型检查时验证，不满足时报错。

#mbt 类型

  • 只有类型参数，没有索引；不是命题，不是 suberror；构造子没有隐式字段。
  • 字段类型是 MoonBit 类型：Int、Double、Bool、Char、String、Unit、类型参数、#mbt 类型，以及它们之间的函数类型。暂不支持数组。
  • 生成的类型名和构造子须以大写字母开头，不能与 Value、Option 等已有名字冲突。

#mbt(“名字”)

对应已有的 MoonBit 类型或 trait，不生成声明。Prelude 中的 Option、Result 就是 #mbt("Option")、#mbt("Result")。从 .mbti 导入的 pub(all) 类型和 pub(open) trait 自动带 #mbt("@pkg.T")（满足条件时）。

#mbt trait

  • Self : Type；父 trait 也是 #mbt。
  • 方法不是泛型的，参数和结果是 MoonBit 类型（可以出现 Self）。
  • 生成的 MoonBit trait 中方法都标 raise（编译后的代码用错误实现控制流）。
  • 原生代码中，约束 [T : Size] 成为 MoonBit 的 fn[T0 : Size]，方法调用成为 Size::size(x)。

#mbt trait 的实例

  • 只有类型参数和 #mbt 约束；Self 是 MoonBit 类型（不能只是一个类型参数）。
  • 遵守 MoonBit 的孤儿规则：已有的 trait（#mbt("…")、导入的）只能为本程序生成的类型实现。
  • 只读（pub）的 trait 不能实现。
  • 方法在原生片段中的实例生成 MoonBit impl。

自动发现可以标 #mbt 的声明

#mbt 是显式的约定，编译器不会自动给声明加上它。但 moonpp check 会检查写了 pub 却没有 #mbt 的 enum、struct、trait 和函数，对能满足 #mbt 条件的给出提示：

src/main/shapes.mbtpp:2: hint: pub type Shape could be #mbt (it would be a MoonBit type)
src/main/shapes.mbtpp:23: hint: pub trait Area could be #mbt (it would be a MoonBit trait)
src/main/shapes.mbtpp:41: hint: pub fn norm1 could be #mbt (it would be exported as a MoonBit function)
  (`moonpp fix` adds #mbt to them)
ok: src/main

moonpp fix 在这些声明上方插入一行 #mbt，然后重新检查包；如果检查失败，就恢复原文件。

  • 只看 pub 声明：pub 在 MoonBit++ 中没有别的含义，这里用它表示“打算给 MoonBit 用“。
  • 类型和 trait 一起判断：互相引用的几个类型可以同时成为 #mbt。
  • 函数需要签名能翻译（假设上面提示的类型都已标注），且函数体在原生片段中（与编译器的检查 相同）。
  • 带索引的类型、提到这些类型的类型和函数、lemma 不会被提示。

#mbt 函数

函数也可以标 #mbt：它会被编译为同名的公开 MoonBit 函数，MoonBit 代码可以直接调用。

#mbt
enum Tree[T] {
  Leaf
  Node(Tree[T], T, Tree[T])
}

#mbt
fn[T] insert(t : Tree[T], x : T, lt~ : (T, T) -> Bool) -> Tree[T] {
  match t {
    Leaf => Node(Leaf, x, Leaf)
    Node(l, y, r) =>
      if lt(x, y) {
        Node(insert(l, x, lt~), y, r)
      } else {
        Node(l, y, insert(r, x, lt~))
      }
  }
}

#mbt
fn[T] Tree::depth(self : Tree[T]) -> Int {
  match self {
    Leaf => 0
    Node(l, _, r) => {
      let a = l.depth()
      let b = r.depth()
      1 + (if a > b { a } else { b })
    }
  }
}

fn main {
  let mut t : Tree[Int] = Leaf
  for i = 0; i < 6; i = i + 1 {
    t = insert(t, i * 7 % 10, lt=(a, b) => a < b)
  }
  println(t.depth())
}

编译结果：

pub fn[T0] insert(t : Tree[T0], x : T0, lt~ : (T0, T0) -> Bool raise) -> Tree[T0]
pub fn[T0] Tree::depth(self : Tree[T0]) -> Int32

（moon fmt 把 MoonBit 的 Int 写作 Int32。）

签名（类型检查时验证）

  • 隐式参数只能是类型参数 [T]；约束只能是类型参数上的 #mbt trait，被约束的类型参数要出现在 参数或结果中。
  • 参数和结果是 MoonBit 类型。
  • 支持 x~、x? 参数，不支持默认值。
  • 方法只能属于本程序生成的 #mbt 类型。
  • main 不能标 #mbt。
  • #mbt("名字") 指定 MoonBit 中的函数名。

函数体（编译时验证）

函数体必须在原生片段中，否则编译报错，并指出第一个不能原生翻译的表达式，例如：

#mbt fn f cannot be compiled to MoonBit: its body is not in the native fragment:
in `println(x)`, println has no native signature (a type without a MoonBit type,
or a bound that is not #mbt)

raise

没有声明 raise 的函数在 MoonBit 中也不 raise，内部的运行时失败（如不完整的匹配）变成 abort。声明了 raise E 的函数在 MoonBit 中是 raise。

在 MoonBit 中使用编译结果

#mbt 的函数、类型和 trait 编译后是公开的，所以 MoonBit 代码可以使用它们。

例如编译#mbt 函数中的程序后，在生成项目的 main/ 目录中加一个 MoonBit 测试文件 export_wbtest.mbt：

test "exported functions" {
  let t = insert(Tree::Leaf, 3, lt=(a, b) => a < b)
  inspect(t.depth(), content="1")
}

然后在生成的项目中运行 moon test。

也可以让别的 MoonBit 项目通过工作区（moon.work）引用生成的项目。

目前生成的总是 main 包（带 main 函数），还不能生成单独的库包。

已知限制

语言

  • 没有终止检查和严格正性检查（按设计）：可以“证明”假命题。
  • 没有可恢复的代数效应，没有 simp、omega、auto 等自动化策略。
  • 局部函数不能递归。
  • 结构体没有可变字段，没有结构体模式。
  • trait 没有默认方法。

导入

  • 解释器不能运行导入的 MoonBit 函数，只能在编译后调用。
  • 不支持 MoonBit 的 async（async fn、async 函数类型）。
  • 导入包中的泛型 impl、trait 对象等不导入（见类型对应与不导入的项）。

编译器

  • 数组在原生代码中不是原生类型：含数组的签名走统一表示，也不能是 #mbt。
  • 统一表示与原生代码之间按值转换，频繁跨边界传递大型数据会慢。
  • 证明不擦除。

工具

  • 生成的项目总是 main 包，不能生成库包。
  • 需要新版 moon（使用 moon.mod / moon.pkg）。
